# Client SDK

The "client SDK" is not an npm package — it's a **self-contained snippet** generated by `buildRnClient({ host, port })` (defined in `src/shared/rnClient.js`). This keeps the debugger dependency-free: nothing is added to your `package.json`.

There are two ways it reaches your app:

- **Automatic** — the **Project** button writes it to `rnspy.connection.js` in your project root, gitignores it, and adds the import for you. See [Automatic setup](#automatic-setup).
- **Manual** — copy the snippet from the app's empty state and paste it into your entry file.

## What the snippet does

On load (inside `if (__DEV__)`), it:

1. **Resolves device identity** — tries `react-native-device-info` for a stable id and a friendly name; falls back to `rn-<random>` and `"React Native"`.
2. **Opens a WebSocket** to `ws://HOST:PORT` and sends a `hello` frame with name/platform on open.
3. **Auto-reconnects** — if the socket closes (app reload, desktop not ready), it retries every **2 seconds**.
4. **Queues offline events** — up to **500** events are buffered while disconnected and flushed on reconnect.
5. **Monkey-patches globals:**
   - `console.log/info/warn/error/debug` — captures args (objects serialized safely, `Error` → `{message, stack}`), plus the **caller file:line:col** parsed from the stack.
   - `fetch` — emits `network-start` then `network` (with status, headers, body, size, duration). Clones the response so your app is unaffected.
   - `XMLHttpRequest` — same fields; de-duplicates `fetch`/`XHR` double-capture via a 5s pending map.
   - `WebSocket` — emits `ws-open`, `ws-frame` (send/recv), `ws-close`, `ws-error`. The debugger's own control socket is excluded.
6. **Wraps React Navigation (if installed)** — `NavigationContainer` gains an `onStateChange` that reports the focused route path on every change, chaining any handler you passed so your own stays intact. Each navigator's `Screen` list is read to learn which component renders which route, which is what lets the desktop find a screen's source file. Purely observational: navigation is never driven from the desktop.
7. **Handles remote commands** — if the desktop sends `{ kind: 'command', command: 'reload' }`, it triggers an RN fast-refresh/reload via `DevSettings`.

## Event protocol (frames sent to the desktop)

| `kind` | Emitted by | Key fields |
| ------ | ---------- | ---------- |
| `hello` | connect | `name`, `platform` |
| `console` | console patch | `level`, `args`, `caller`, `stack` |
| `network-start` | fetch/XHR open | `id`, `method`, `url`, `requestHeaders`, `requestBody` |
| `network` | fetch/XHR done | `id`, `status`, `responseHeaders`, `responseBody`, `size`, `duration` |
| `ws-open` | WS open | `wsId`, `url`, `protocols` |
| `ws-frame` | WS message | `wsId`, `dir` (`send`/`recv`), `data`, `size` |
| `ws-close` | WS close | `wsId`, `code`, `reason` |
| `ws-error` | WS error | `wsId` |
| `navigation` | route change / `navigation-read` | `stack` (focused path, root first), `routeName`, `prevRouteName`, `screens`, `available`, `diag` |
| `navigation-registry` | navigator mount | `screens` (`{ routeName: componentName }`) |

Each frame is also stamped server-side with `seq`, `deviceId`, `clientId`, `clientName`, `clientPlatform`, and `receivedAt`.

## Automatic setup

Click **Project** in the header (or **Set it up for me** in the empty state), pick the folder holding your `package.json`, review the previewed changes, and confirm.

The generated `rnspy.connection.js` is the same snippet with the paste instructions swapped for a generated-file banner, host and port already substituted, and the `__DEV__` guard intact. Because it's its own module, the entry file only gains one line:

```js
import './rnspy.connection' // @generated-by rnspy-devtools — dev only, safe to delete
```

That line goes in as the **first** import, after only a shebang, leading comments, or a `'use strict'` directive. Ordering is load-bearing — see [Limitations](#limitations).

Detection requires `react-native` in `dependencies` or `devDependencies`. The entry file is resolved from `package.json` `main`, falling back to `index.js`/`App.js` and their `.jsx`/`.ts`/`.tsx` variants; Expo's `node_modules/expo/AppEntry.js` is skipped in favor of your own `App.tsx`.

The operation is idempotent and reversible. Files are backed up as `<file>.rnspy.bak` before modification, re-running reports **Up to date** rather than duplicating lines, and **Remove integration** deletes the generated file and strips the import. Changing the port later shows a pending **Regenerate** step for the connection file.

## Embedding it your way

The snippet is plain JavaScript and runs through RN's `require`, so it works in both **Expo** and **bare** RN. You can:

- Let the **Project** button generate `rnspy.connection.js` and wire it up (above).
- Keep it inline at the top of `index.js`.
- Move it to its own module (e.g. `rnspyClient.js`) and import it first.
- Hard-code `RNSPY_HOST`/`RNSPY_PORT` instead of using the generated values (handy for CI or fixed setups).

### Example as a separate module

```js
// rnspyClient.js
export function connectRnspy(host, port) {
  if (!__DEV__) return
  // paste the generated snippet body here, using host/port params
}

// index.js
import { connectRnspy } from './rnspyClient'
connectRnspy('192.168.1.20', 8097)
```

## Limitations

- Patches are global; they don't capture traffic from libraries that cache the original `fetch`/`WebSocket` reference **before** the snippet runs. Always import the snippet first.
- Request/response bodies are captured as text; very large bodies may be truncated by the desktop buffer caps (see [Features](./features.md)).
- The snippet is **dev-only** by design — never ship it to production (keep the `__DEV__` guard).
- Navigation capture needs `@react-navigation/native` and the app's own `NavigationContainer`. **Expo Router is not supported** — it builds its container internally, so there is nothing to wrap. Route params over 4 KB are reported by size instead of being sent.

## Removing the debugger

If you used automatic setup, open **Project** and click **Remove integration** — it deletes `rnspy.connection.js` and removes the import line. The `.gitignore` entries are left in place, since removing them risks clobbering unrelated edits.

If you pasted manually, delete the snippet (or the whole `if (__DEV__)` block) from your entry file and reload. Either way, no package uninstall is needed.
